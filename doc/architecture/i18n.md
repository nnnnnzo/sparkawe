# Interface multilingue

Spark affiche son interface en huit langues : français, anglais, espagnol, allemand, italien, portugais, japonais et chinois simplifié. La langue se choisit dans **Paramètres → Langue** et s’applique à chaud, sans redémarrage et sans remonter le workspace.

## Source de vérité

| Élément | Fichier |
|---|---|
| Langues, détection, formats | `src/core/i18n.ts` |
| Dictionnaires par domaine | `src/core/locales/*.ts` |
| Locale courante et `t` global | `src/i18n/index.ts` |
| Hook React `useI18n` | `src/i18n/react.ts` |
| Réglage persistant | Snapshot `settings` de `spark.db`, champ `locale` |

Chaque domaine (`shell`, `store`, `terminal`, `markdown`, `data`, `explorer`, `preview`, `openalex`, `errors`, `manifests`) expose un objet plat :

```ts
const messages = {
  "store.nav.discover": {
    fr: "Découvrir",
    en: "Discover",
    es: "Descubrir",
    de: "Entdecken",
    it: "Scopri",
    pt: "Descobrir",
    ja: "見つける",
    zh: "发现",
  },
} satisfies Record<string, Record<Locale, string>>;
```

- Une clé doit exister dans les huit langues : TypeScript refuse une langue manquante.
- Les clés sont préfixées par leur domaine ; `src/core/locales/index.ts` fusionne les objets.
- `tests/i18n.test.ts` vérifie l’absence de doublons entre domaines, les espaces réservés et les variantes plurielles.

## API

```ts
import { localized } from "../core/i18n.ts";
import { t } from "../i18n/index.ts";
import { useI18n } from "../i18n/react.ts";

const { locale, t, tp, text } = useI18n();
```

- `t(clé, params?)` traduit et interpole `{name}`, `{count}`, etc.
- `tp(clé, count, params?)` choisit `.one` ou `.other` avec `Intl.PluralRules`, puis retombe sur `.other`.
- `text(valeur)` résout un `LocalizedText` ; `locale` sert aux formats `Intl`.
- `localized(clé)` produit `{ key }` pour les champs de manifeste, de tuile, d’action ou de commande.
- `resolveText(valeur, locale)` et `translate(locale, clé)` sont les variantes pures utilisées par le noyau et les tests.

Dans les effets qui possèdent une ressource (PTY, CodeMirror, worker PDF, abonnement de données), utiliser le `t` global importé de `src/i18n/index.ts`. Ne jamais ajouter `t` ou `locale` aux dépendances de ces effets : la langue change les libellés, pas la ressource.

## `LocalizedText`

`src/sdk/index.ts` définit :

```ts
type LocalizedText = string | { readonly key: string };
```

Les champs concernés :

- `Manifest.name`, `subtitle`, `summary`, `description` ;
- `TileDefinition.title`, `guide` ;
- `TileAction.title`, `description` ;
- `Command.title`, `category`.

Les paquets importés fournissent des chaînes : elles restent inchangées. Les extensions intégrées passent des références `localized("...")`. `Manifest.category` reste une chaîne stable (`development`, `data`, `files`, `writing`, `research`, `reading` pour les intégrées), affichée par le Store via une table de libellés.

## Détection et repli

`detectLocale(navigator.languages)` compare la base de chaque étiquette (`fr-CA`, `en_GB`, `zh-Hant`) aux huit langues. Si aucune ne correspond, le repli est l’anglais. Un `locale` enregistré dans les réglages gagne toujours sur la détection.

La chaîne de repli est : langue choisie → anglais → clé brute. Une clé absente ne casse donc pas l’interface.

## Formats

- Nombres : `Intl.NumberFormat(locale)` via `formatNumber` ou directement dans le composant.
- Dates : `Intl.DateTimeFormat(locale)` / `toLocaleDateString(locale)`.
- Tri et recherche : `localeCompare(..., locale)`, `toLocaleLowerCase(locale)` ; la recherche du Store conserve la normalisation NFD qui ignore les accents.
- `document.documentElement.lang` est mis à jour à chaque changement.

## Ajouter une langue

1. Ajouter le code à `LOCALES` et une entrée à `LANGUAGES` dans `src/core/i18n.ts` (nom natif + emoji drapeau).
2. Le compilateur signale chaque clé manquante dans chaque fichier `src/core/locales/*.ts`.
3. Vérifier les écarts de mise en page (mots longs, CJK) dans la fenêtre de développement.
4. Ajouter la langue aux tests de détection et de parité.
5. Mettre à jour ce document et le README si la liste change.

## Limites assumées

- Les descriptions d’outils du pont MCP et les messages d’erreur natifs Rust restent hors périmètre de cette passe. Les titres, guides et actions partagés avec le MCP suivent la langue de l’interface.
- Les métadonnées d’un paquet importé ne sont pas traduites par l’hôte ; une localisation déclarative des paquets pourra être ajoutée plus tard sans changer le format actuel.
- Aucun support RTL n’est proposé aujourd’hui.
